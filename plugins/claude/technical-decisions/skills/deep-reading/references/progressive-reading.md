# Progressive Reading Method

## 0. Document Profile
Always place provenance first.

Capture when available:
- Title
- Author(s)
- Affiliation / publisher
- Document type
- Published date
- Last updated date
- Version
- Original source
- Source URL
- Source status: e.g. preprint, peer reviewed, company self-published, secondary reporting, community discussion
- Source note only when it materially changes interpretation

Use `未確認` for unknown fields. Do not infer missing metadata.

## 1. ORIENT
Identify:
- document type and author/source purpose
- major parts and relationships
- main line vs supporting material
- whether a single core claim actually exists

Adapt the map:
- Research paper: Research Question → Method → Evidence → Results → Limitations
- News/newsletter: Main Story → Supporting Information → Other Topics → Source Quality
- Opinion: Claim → Argument → Evidence → Assumptions
- Tutorial/documentation: Goal → Preconditions → Procedure → Constraints → Failure Modes

## 2. READ — Chinese Semantic Reconstruction
After understanding the whole source, reconstruct it in natural Traditional Chinese.

Do not translate sentence-by-sentence and do not over-compress. Preserve details that change understanding: facts, arguments, examples, data, author stance, transitions, and subtle qualifications. Reordering for comprehension is allowed if meaning is preserved.

Prefer continuous narrative over excessive tables and fragmented bullets.

## 3. UNDERSTAND
Add only prerequisites that materially improve comprehension. On first use of an important term:
1. retain the English term;
2. explain it in plain Traditional Chinese;
3. state its role in this document;
4. add an example/analogy only when useful;
5. connect it to other core concepts when needed.

For argumentative material, reconstruct:
`Observation/Problem → Assumption → Method/Evidence → Inference → Result → Conclusion`

Flag causal claims, hidden assumptions, inference jumps, evidence-to-claim links, correlation/causation issues, and author interpretation.

## 4. DISTILL
Do not repeat READ. Extract only durable knowledge:
- Facts
- Concepts
- Methods / Frameworks
- Claims
- Generalizable Principles

Use the test: `讀完後，我以前不知道、現在值得知道的是什麼？`

## 5. CHALLENGE
Inspect only issues that could materially change the conclusion:
- assumptions
- evidence/source quality
- benchmark/statistical/case fairness
- alternative explanations
- applicability boundaries
- over-interpretation
- omissions

When useful, classify claims:
- A — sufficiently supported
- B — reasonably supported with uncertainty
- C — author speculation/opinion
- D — insufficient evidence

End substantial Deep analysis with an **Evidence Verdict** of 2–4 sentences: what the document can legitimately support, and what it should not be used to prove.

## 6. DERIVE
Only after comprehension and challenge, derive new insights.

Label important insights:
- `【文章直接提出】`
- `【根據文章推導】`

For derived insights, use a compact chain:
`Evidence A + Evidence B → Reasoning → Insight`

Do not manufacture novelty when evidence is insufficient.

## 7. CONNECT
Only now use relevant user context. For each material connection:
`Document knowledge → relevance → hypothesis → validation still needed`

Classify as directly applicable, worth borrowing, worth experimenting, or surface similarity only.

## 8. APPLY
Run only when the source has actionable value. Possible outputs: framework, checklist, design principle, working method, hypothesis, MVP experiment, further research question. It is valid to conclude that no immediate action is warranted.

## 9. RETAIN
Rank by knowledge value rather than source order.

Each item includes:
- What
- Why
- Confidence: sufficiently supported / reasonably supported / derived insight

End with one mental model that best compresses the document.
