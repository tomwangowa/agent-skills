# 決策：回饋功能只產生預填的 Teams 聊天連結

日期：2026-10-07  
狀態：Tom 於 2026-10-07 選定；實作版本 0.4.0。

## 脈絡

attention-mod 的不變條件是被動觀察：不用 store、檔案、http、process，也不提交主對話提示。回饋功能必須把使用者的文字送到某處，所以先決定送去哪。

## 決策

- 面板內「回饋」按鈕＋單行輸入框，Enter 後產生 Teams 聊天 deep link（`https://teams.microsoft.com/l/chat/0/0?users=…&message=…`），用 `Link` 顯示，並提供 `$.ui.copy` 複製純文字。
- 收件人由 `userConfig.feedbackRecipient` 提供，程式碼與 repo 不含任何地址（repo 公開）；沒設定時只提供複製內容。
- 不破例：不寫檔、不用 store、不發 http；使用者在 Teams 按 Enter 才會送出，Mod 不自動送出。
- 連結只含使用者輸入與分類標籤；不附 session、對話、路徑、工具內容或版本資訊。

## 修訂紀錄

- 初版（同日稍早）：預填 GitHub new-issue 連結。實測發現瀏覽器登入 GitHub EMU 帳號時，GitHub 回「Unable to create issue」，EMU 帳號無法對企業外的 repo 建立 issue；受眾主要是公司同事，所以改用 Teams。
- Tom 實測 `https://` 與 `msteams://` 兩種連結都可開啟；採用 `https://`，因為遠端 surface 的 `Link` 只接受 https，而且網頁版 Teams 可作後備。

## 考慮過但未採用

| 方案 | 未採用原因 |
|---|---|
| 本機 JSONL（`$.fs`） | 需放寬「不用檔案」，且資料留在使用者本機，不會自動到維護者手上 |
| GitHub issue 連結 | EMU 帳號無法建立 issue，受眾是公司同事，多半走不通 |
| `mailto:` | 需要預設郵件程式，網頁信箱使用者點了沒反應；Teams 是同事日常工具 |
| `$.store` | 需放寬「不用 store」，使用者難以取出 |
| 只存記憶體 | 重載即消失，等於無法收集回饋 |
| `/feedback` 指令 | 使用者選擇面板內輸入 |

## 限制

- 收件人需與使用者在同一個 Teams 租戶；連結長度上限約 2,000 字元，收件人 email 約 25 字元時單行約 200 個中文字或 1,800 個英文字母，超過會截斷連結內的文字並提示（複製內容不受限）。
- 草稿在 `session-reset`（`/clear`、`/resume`、session 結束）時清空。
- `message` 預填在 Teams 端的實際長度上限、公司資安政策是否擋 `msteams://`，只靠 Tom 單次實測，未做系統性驗證。
- VERIFIED（Tom 手動）：Teams `https://` 與 `msteams://` 連結可開啟。
- NOT VERIFIED：面板內從點連結到 Teams 預填的完整流程、真實終端機與 Desktop 的輸入框焦點、`ui.copy` 實際寫入剪貼簿、`feedbackRecipient` 在安裝畫面與 `/config` 的呈現。目前只有原生測試套件（terminal／desktop 兩種 surface）驗證元件樹與事件處理。
