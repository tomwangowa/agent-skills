# 決策：回饋功能只產生預填的 GitHub issue 連結

日期：2026-10-07  
狀態：Tom 於 2026-10-07 選定；實作版本 0.4.0。

## 脈絡

attention-mod 的不變條件是被動觀察：不用 store、檔案、http、process，也不提交主對話提示。回饋功能必須把使用者的文字送到某處，所以先決定送去哪。

## 決策

- 面板內「回饋」按鈕＋單行輸入框，Enter 後產生 `tomwangowa/agent-skills` 的預填 new-issue 連結，用 `Link` 顯示，並提供 `$.ui.copy` 複製。
- 不破例：不寫檔、不用 store、不發 http；送出動作由使用者在 GitHub 頁面完成。
- 連結只含使用者輸入與一行固定說明；不附 session、對話、路徑、工具內容或版本資訊。

## 考慮過但未採用

| 方案 | 未採用原因 |
|---|---|
| 本機 JSONL（`$.fs`） | 需放寬「不用檔案」，且資料留在使用者本機，不會自動到維護者手上 |
| `$.store` | 需放寬「不用 store」，使用者難以取出 |
| 只存記憶體 | 重載即消失，等於無法收集回饋 |
| `/feedback` 指令 | 使用者選擇面板內輸入 |

## 限制

- 需要 GitHub 帳號；連結長度上限約 2,000 字元，單行輸入約 110 個中文字或 1,400 個英文字母，超過會截斷並提示。
- issue 開在公開 repo，面板的說明文字和 README 都提醒不要貼敏感內容。
- 草稿在 `session-reset`（`/clear`、`/resume`、session 結束）時清空。
- NOT VERIFIED：真實終端機與 Desktop 的輸入框焦點、連結點擊開啟、`ui.copy` 實際寫入剪貼簿。目前只有原生測試套件（terminal／desktop 兩種 surface）驗證元件樹與事件處理。
