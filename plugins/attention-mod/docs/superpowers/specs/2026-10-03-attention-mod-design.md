# 「你到底在忙什麼」Attention Mod 設計

日期：2026-10-03  
狀態：Tom 已於 2026-10-03 確認書面規格，可作為實作依據。  
選定方向：事件狀態＋有限範圍的背景摘要。

## 使用目的與範圍

Tom 離開目前的 Claude Code 工作階段後，回來看側邊面板，就能接回工作脈絡，了解正在執行的動作、最近取得的證據，以及有沒有待他處理的事項。

第一版只觀察當前工作階段的既有對話與工具事件。摘要在主對話之外產生，寫入面板狀態；不要求主 Claude 額外回報進度。

不包含跨工作階段總覽、macOS 通知、LINE／Discord、代回訊息、停止或改派主工作、歷史回放、持久化紀錄。側邊面板的選擇不代表擴充資訊範圍。

## 面板

面板標題為「你到底在忙什麼」，預設顯示，不搶輸入焦點。終端機寬度不足時，依 Claude Code 的原生面板規則改放在輸入框上方；不自行強制側邊配置。使用者關閉面板後，不因摘要更新而重新打開；重新開啟面板的本機指令為 `/attention`，不啟動主 Claude 的新回合。

以下是假想工作階段的文字範例：

```text
你到底在忙什麼

目標：修正登入失敗
脈絡：Claude 懷疑 token 過期處理有問題
動作：正在跑登入測試
證據：上一輪仍有 2 項失敗
需要你：目前沒有待回覆訊號

脈絡與證據更新：20 秒前
```

「目標」「脈絡」「證據」來自背景摘要。「動作」「需要你」由事件狀態產生，不能被摘要模型覆寫。面板保留各來源的時間；即時動作更新不會讓舊摘要的時間看起來變新。

缺乏資料時顯示「尚無摘要」或「目的尚不清楚」。長時間沒有事件只表示「多久沒有觀測到新事件」，不能據此判定卡住、沒有進展或快完成。回合結束只表示「本回合已結束」，不等同任務完成。

## 元件與資料流

### 事件觀察器

觀察工作階段、使用者提示、主工作回合與工具呼叫的生命週期；將原事件與原結果交還後續處理，不改寫提示、結果或權限決定。具體事件欄位以本機 Claude Code 產生的型別為準。

記錄當前目標的來源文字、近期對話、工具名稱、參數節錄、結果節錄、狀態、時間與來源識別。工具成功、失敗、拒絕、取消及執行中必須分開；一般工具成功不能被翻成「需求已完成」。

並行工具以工具呼叫識別追蹤。畫面可以顯示多個動作或「共 N 個工具執行中」，其中一個完成不能清掉其他仍在執行的動作。可辨識的子代理事件不覆蓋主工作的目前動作；主對話裡出現的子代理回報仍可作為摘要素材，保留來源身分。

只有可確認的待回答問題或人工授權等待，才顯示需要 Tom 處理。`tool.check` 的 `ask` 結果本身不保證正在等待人工，不能單獨當作等待證據。若本機事件不足以可靠判斷，顯示「等待狀態不明」；沒有觀測到等待訊號也不宣稱已證明不需要人。

### 素材整理器

每次摘要以當前工作階段的來源紀錄建立不可變快照。先保留目前目標的來源，再納入近期使用者補充、Claude 自述與工具結果；整份素材連同來源標記及省略標記，總長最多 8,000 字元，按 Unicode code point 計算。超過上限時優先丟棄較舊的非目標素材；目標來源本身過長時也須節錄。明示節錄或省略，不能拼成假裝完整的原文。

不把上一份模型摘要當成新的證據，不額外讀取工作區檔案，也不把整份系統提示或所有 Skills 加進素材。若工作目標尚未能由原文確定，允許摘要標示不清楚，不從工具檔名猜目標。

每段素材保留來源識別、身分與時間。外部內容、工具輸出和引用文字以資料區塊提供；摘要提示要求它們不能成為新的工作指令。

### 背景摘要器與排程器

使用 `$.model.complete`，預設模型為 `haiku`。回應為結構化 JSON，只包含目標、工作脈絡、最近證據與各自的來源識別；每個非空摘要欄位都必須引用快照內存在的來源。缺乏依據的欄位回傳 null，由面板顯示資訊不足，不要求模型為未知狀態編造來源。Claude 自述的假設保留假設語氣，不能升級成已驗證結果。

工程預設為單次最多 512 個輸出 tokens，15 秒逾時。這些是原型的用量與等待上限，不是已量測的成本或速度保證。

有新素材才排程。兩次模型呼叫的開始時間至少相隔 60 秒，同時最多一個呼叫；呼叫進行中到達的新素材留待下一次合法更新。無新素材不呼叫；若模型失敗，也不能無限自動重試同一份素材。

模型呼叫在背景計時器執行，不讓工具事件或畫面繪製等待模型回答。呼叫期間，目前動作仍由新事件更新。背景回應不得觸發主對話的新提示或新回合。

接收回應時驗證格式、欄位、長度與來源識別；目標、脈絡及證據各為一段最多 160 字元的文字。2026-10-04 Tom 選擇 A：原文 JSON 或完整、單一的 JSON code block 均可接受，只移除完整外框；前後夾帶說明、多個區塊或不合 schema 仍整份拒絕。脈絡引用只容許 assistant 來源，證據引用只容許工具結果來源；來源身分不合或引用不存在的來源，整份回應不採用。來源存在只能證明可追查，不能自動證明摘要語意正確；這仍須人工抽查。

### 面板狀態

狀態只存在目前執行的 Mod 記憶體，不寫入 `$.store` 或其他檔案。摘要完成後只更新文字摘要及其時間，不覆寫較新的工具狀態。

每份快照與回應攜帶工作階段識別及本地世代編號。清除、切換或重載後使舊世代失效；舊呼叫即使無法取消、之後才回答，也不得寫入新世代。同一工作階段收到新的使用者提示時，也使前一份摘要失效並從目前對話重建素材，以免改換任務後沿用舊目標；工具仍依實際生命週期追蹤，不因新提示假裝已結束。

同一世代的快照之後若已有新素材，面板標示「有新活動，摘要待更新」，不能把新活動當作舊摘要已涵蓋。摘要時間以素材快照時間計算，不能用回應抵達時間掩蓋模型處理期間的新活動。60 秒呼叫間隔與同時最多一個呼叫的限制跨清除／切換持續有效，直到 Mod 卸載或重載；使舊回應失效不會提早釋放仍在執行的呼叫。

## 失敗與生命週期

模型沒有回答、逾時、被政策拒絕或回應不合規格時，保留上一份摘要及原時間，顯示「摘要更新失敗」。沒有上一份時維持「尚無摘要」。事件與主 Claude 照常執行。

清除或切換工作階段時清空目標、事件、等待訊號、摘要與排程素材；重新取得當前工作階段資料後才能產生新摘要。關閉工作階段或卸載時停止背景更新。重載後從目前對話重建有限素材，不能沿用前次的等待狀態。

不能假設 `/clear`、`/resume`、`/branch` 會重新觸發 `session.start`。重設與重建須依 `session.end` 等可用事件及實際工作階段識別核對，且在採用背景回應前再次確認世代。

## 驗證與原型判準

自動化檢查須實際驗證下列行為，不能只驗證模擬模型回傳的字串：

- 原事件及工具結果照常傳遞，背景摘要不提交主對話提示；延遲或失敗的模型回應不阻止工具事件完成。
- 60 秒開始時間間隔、同時最多一個呼叫、無新素材不呼叫、失敗不無限重試；素材確實不超過 8,000 字元。
- 模型逾時、格式錯誤、未知來源、素材不足時正確降級，且保留舊摘要的時間。
- 並行工具獨立結束；明確等待訊號與等待解除有對應狀態，權限路由的 `ask` 不直接等同人工等待。
- 新使用者提示、清除、切換、重載與較晚到達的舊世代回應不混入新任務；新活動不被舊摘要時間掩蓋，切換不繞過呼叫間隔或並行限制。
- 側邊／窄終端機面板、關閉及 `/attention` 重開不搶輸入焦點，不啟動主工作新回合。

真實原型另驗證一段正常工作、一段失敗調查及一次任務切換，人工將摘要與來源對照，檢查有無捏造、過時假設或錯誤的完成宣告。記錄摘要呼叫數、可取得的用量及主工作是否出現阻塞；模擬測試不能替代這項驗證。

若無法在主 Claude 執行時讀取必要素材，或摘要呼叫阻塞主工作，暫停擴充並重新評估這條路。若摘要語意無法忠於來源，保留事件狀態而不發布看似可靠的脈絡摘要。
