# 從第 0 個到第 1 個：你的 AI Skill 行動指南

> *這是「當 AI 越來越好用，品質反而越來越差」系列的第 14 篇。*
> *這一篇講的是：怎麼找到你的第一個痛點，然後把它變成一個 skill。*

---

前面 13 篇，我從踩坑講到體系，從 code review 講到 prompt engineering 的局限。如果你看到這裡還沒有動手，這一篇就是為你寫的。

不需要像我一樣造 32 個 skills。你只需要**一個**。

---

## 你每天最煩的事是什麼？

我在公司內部辦過 2 次 Skill Workshop，對象有 RD/HIE/PM 同事。

PM 的日常跟工程師很不一樣。他們不寫程式碼，但他們每天都在處理大量重複性的工作——寫週報、整理會議紀錄、追蹤 follow-up 事項、彙整跨團隊的進度。

他們有自己的工具組合：email、Teams、Excel、PowerPoint、筆記本、ChatGPT。每個工具各司其職，拼拼湊湊也能把事情做完。但如果你仔細看，他們做的每一件事都是 workflow——只是他們沒有意識到這一點。

每次 workshop 開場，我都不給固定的範例。我只問一句話：

**「你們覺得每天最煩的事情是什麼？」**

這個問題比「你想用 AI 做什麼」好得多。因為「想用 AI 做什麼」會讓人想到很酷但不實際的事。而「每天最煩的事」直接指向真實的痛點。

---

## 現場就做出來了

Workshop 裡，PM 同事現場就實作出了自己的第一個 skill。

有人做的是**週報生成**：每週把素材丟進去——本週完成了什麼、遇到什麼阻礙、下週計畫是什麼——skill 會按照固定格式整理成一份週報。不用每次重新想格式，不用每次重新組織結構。

有人做的是**會議總結**：把會議紀錄或錄音逐字稿丟進去，skill 會整理出重點摘要，然後自動列出 follow-up 事項和負責人。以前這件事要花半小時手動整理，現在幾分鐘搞定。

這些 skills 技術上都不複雜。但它們解決的問題很真實——每天都會遇到、每次都很煩、每次都在重複同樣的判斷。

---

## 找到你的第一個 Skill 的方法

不管你是工程師、PM、設計師，方法都一樣：

**第一步：列出你這週重複做了三次以上的事。**

不用想太大。寫 code review、整理會議紀錄、回覆固定格式的郵件、產生測試報告、彙整進度更新——這些都算。

**第二步：從裡面挑一件「每次做都覺得煩」的。**

「煩」是一個很好的信號。它代表這件事有明確的流程（所以你覺得重複），但你每次都得從頭來（所以你覺得煩）。

**第三步：問自己——「如果有人幫我做，我會怎麼交代他？」**

這是最關鍵的一步。你交代的內容，就是 skill 的雛形。

- 「先看 diff，然後檢查邏輯正確性、邊角案例、錯誤處理⋯⋯」→ 這就是 code-review skill
- 「把會議紀錄整理成重點，列出 action items 和負責人」→ 這就是會議總結 skill
- 「拿這些素材，按照這個格式寫週報」→ 這就是週報 skill

你發現了嗎？**你已經知道該怎麼做了。** 你只是沒有把它寫下來。

**第四步：寫下來。**

不需要完美。先寫一個最粗糙的版本，跑一次看看。不對的地方再調整。我自己的 skills 也是這樣迭代出來的——沒有任何一個是第一版就定稿的。

## 常見的卡關點

在 workshop 裡，我觀察到幾個新手常卡住的地方：

**「我不知道要做什麼 skill。」**

回到那個問題：你每天最煩的事是什麼？如果真的想不到，回顧你上週的行事曆，找出你花最多時間在「不需要創意但不能省略」的事情上。那就是你的第一個 skill。

**「我覺得這件事太簡單，不值得做成 skill。」**

越簡單越好。你的第一個 skill 不需要有八個階段和兩個 gate check。它只需要解決一個具體的、重複的問題。簡單的 skill 讓你快速看到效果，效果給你動力做第二個。

**「我不會寫程式。」**

Skill 不是程式。它是一份指示——告訴 AI 在什麼時候、按照什麼標準、做什麼事。如果你能寫一封交接郵件，你就能寫一個 skill。PM 同事在 workshop 裡不需要寫任何一行程式碼就做出了自己的 skill。

## 從 1 到 N 是自然的

有了第一個 skill 之後，你會開始注意到更多「可以被自動化的重複判斷」。

這不是因為重複的事變多了，而是因為你的雷達打開了。

以前你不會想到「這件事可以讓 AI 按照我的標準做」，因為你沒有這個框架。有了第一個成功經驗之後，你看每件事都會多一個問題：「這件事，我能寫成 skill 嗎？」

不用急。不用一口氣造 32 個。讓它自然長出來就好。

我自己的 32 個 skills 是三個月裡慢慢累積的。每次遇到一個痛點，造一個 skill。遇到體系的問題，造一個 meta skill。沒有計畫表，沒有路線圖。就是**痛點驅動**。

---

## 帶走一件事

不要想「我要建立一套 AI 工作流體系」。那太遠了。

想這個就好：**「我這週最煩的那件事，能不能不要再煩了？」**

找到它。寫下來。跑一次。

那就是你的第一個 skill。
