# Before / After 教材

> 全部取自一份真實的「去 AI 味」前後對照（我自己的 sharing 簡報稿，已匿名）：AI 味原版 → 去 AI 味成品。
> 改寫前讀一遍，抓「每條規則實際長怎樣」的手感。**注意**：成品在「對付 / 痛點 / 不是X是Y」這幾條上比 SKILL.md 規則寬鬆（成品保留了一些），因為 Tom 在 brief 裡選了更嚴格的版本——學**口吻**看這裡，但**規則尺度以 SKILL.md（brief 嚴格版）為準**。

---

## 規則 1：戰爭隱喻 → 平實動詞

| Before（AI 味） | After（去 AI 味） |
|---|---|
| 先講結論：我在跟三種「不確定性」**作戰** | 先說結論：真正卡住我的，是三種「搞不清楚的狀況」 |
| 先看我每天的**戰場** | 先看我每天實際碰到的狀況 |
| 效率跟信心同時**被殺** | 時間就這樣被吃掉，對結果的信心也跟著動搖 |

（SKILL.md 嚴格版額外要求：連「對付」也換成「處理 / 一根對應一種」。成品其實留了「對付」，但規則照 brief。）

---

## 規則 2：「不是 X，是 Y」對仗 → 軟化、展開

| Before | After |
|---|---|
| 真正讓我「快又不出錯」的，**不是**更會寫 prompt，**是**趕走三種不確定性 | 讓我又快又少出錯的，其實**不是**我比較會跟 AI 下指令，**而是**我把三種「搞不清楚的狀況」清掉了 |

技巧：`是`→`而是`、把短對仗展開成口語長句、每段／每頁只留 1–2 處硬對仗。

---

## 規則 3：罐頭句尾 → 每次不同的自然句

`.bak` 每根柱子結尾都來一句「**可偷走的招式：**」。成品把每一處都改成不同講法：

| Before（同一個模板） | After（每處都不同） |
|---|---|
| 可偷走的招式就這句：你不擁有的上下游，把它 mock 起來 | 所以這根柱子如果要帶一招走，就是這句：你管不到的上下游，把它 mock 起來 |
| 可偷走的招式：把你跑過、驗證過的互動留下來 | 所以這招你也可以拿去用：把你跑過、而且驗證過是對的互動留下來 |
| 可偷走的招式：契約別留在腦袋跟 PR 串裡，寫進 skill | 我自己的心得是：這種規矩別只留在腦袋跟 PR 討論串裡，把它寫進 skill |
| 可偷走的招式：造之前先問這三題 | （改成）我自己的體會是，知道什麼時候「不該做」，跟知道什麼時候「該做」，其實一樣重要 |
| 可偷走的招式：別讓上下文隨對話關掉就消失 | 我的建議是：別讓重要的上下文跟著對話視窗一起消失 |

## 規則 4：台灣慣用詞

| Before | After |
|---|---|
| 隨時有人合併新**代碼** | 隨時有同事把新**程式碼**合併進來 |
| 同步所有合作 repo（同步**代碼**） | 同步所有合作的 repo（同步**程式碼**） |

## 規則 5：口頭禪節制（痛點 → 變化）

| Before | After |
|---|---|
| 哪一種不確定性最**痛** … 挑最**痛**的那一種 | 哪一種不確定最讓你**頭痛** … 挑最**頭痛**的那一種 |

同一段內反覆的「痛」拆成「痛 / 最痛的 / 頭痛 / 卡住 / 麻煩」輪替。

## 規則 6：專名第一次出現就白話解釋（一句，不囉嗦）

| 專名 | 成品補的白話解釋 |
|---|---|
| mock | 「就是寫一個『假的替身』，長得跟真的服務一樣會回話，但完全跑在我自己電腦裡、我說了算」 |
| harness | 「你可以把它想成『我事先替 AI 搭好的一個工作架子』，讓它每次上工都站在同一個地方」 |
| skill | 「你可以把它想成一張『給 AI 看的小抄』，把規矩白紙黑字寫下來，AI 上工前會先讀」 |
| e2e 測試 | 「end-to-end 測試（就是從頭到尾跑完整條流程的測試）」 |
| Snowflake | 「一種數字型的唯一識別碼」 |
| orphan | 「孤兒資料，主體刪了、附屬的卻沒清乾淨」 |
| dry-run | 「先空跑一遍、印出『等一下會刪掉幾筆』給我看」 |
| regression test | 「回歸測試（就是改完東西，回頭確認舊功能沒被改壞）」 |
| symlink | 「一個捷徑連結」 |
| md5 | 「內容的校驗碼…完全一樣，代表一字不差」 |
| drift | 「這個現象有個名字叫 drift、飄移」 |

**反例（不要做）**：DB、CI、API、commit、schema、Postgres、emulator → 工程師都懂，**不解釋**，硬解釋反而像說教、浪費篇幅。

## 規則 7：壓縮句展開成完整白話（買到邏輯，不灌水）

**Before（跳太快）：**
> App 把 request 透過一個中間層、用一套溝通協定傳到我的 AI agent，agent 收到會寫進它自己的資料庫、再呼叫一個下游服務，最後回給 App。

**After（補上被跳過的環節，每一步都交代「是什麼、去哪、為什麼」）：**
> 使用者在 App 上送出一個請求，這個請求會先經過一個中間層、用一套溝通協定，傳到我負責的 AI agent；agent 收到之後，會把資料寫進它自己的資料庫，再去呼叫另一個下游服務，最後把結果回傳給 App。重點是，這一整條路徑橫跨好幾個團隊、好幾個程式碼倉庫（repo），不是我一個人管得到的。

字數變多，但買到了：中間層的角色、協定是什麼、為什麼這條鏈難管。這不是灌水。

逐類拆解：
- **翻成中文（C 填充詞）**：Hi→大家好、user→使用者、response→回傳的內容、他→它。
- **凍結不動（A 名字）**：`access_token`／`refresh_token`／`id_token`／`offline_access`——一字未改（Guard 1）。

| 這個 case 我再 check 一下 | 這個案子我再確認一下 |

## 事實凍結實證（Guard 1）

整份 diff 裡，**所有事實層 token 一字未動**——這是 Guard 1 該達到的標準。範例性的受凍結 token（已匿名）：

`127.0.0.1:8080` · `:9000` · `/api/reset` · `BACKEND_API_URL=localhost:9000` · `mock_server.py` · `test_lifecycle.py` · `account_id`（18 位）· 十幾張表、跨好幾個 schema · `md5: a1b2c3d4` · `artifacts/transcripts/` · 幾個合作 repo 的名字

要點：數字、port、檔名、識別字、設定值、hash 一律原樣保留，不翻譯、不改格式。

## 語意凍結實證（Guard 2）：把「怪字」標記、不要默默改

一個真實事故（已匿名），正是 flag-don't-fix 的活教材：

> 某個領域 skill 的 SKILL.md 裡寫「雙寫順序：先寫上游、後寫**小薇**」。「小薇」（化名）看起來像打錯、或像某個系統名——但它**其實是一位同事的名字**：她負責那塊 agent DB，所以作者用她的名字當那個 DB 的口語代稱。對外讀者不認識「小薇」，照字面留著會被當成某個系統，所以**對外稿一律改寫成 `agent DB`**。

關鍵：這個「小薇 → agent DB」的判斷是**作者拍板的語意決定**，不是 editor 看到怪字自己默默改。editor 該做的只有三件事：**標記、附解讀、問**。
