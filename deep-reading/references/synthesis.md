# Multi-source Synthesis

Use when multiple sources or an explicit synthesis goal require reasoning across documents. Do not label differences as disagreements until definitions, scope, population/task, evidence type, and time period have been normalized.

## 1. Source Inventory
Record each source's provenance, type, scope, and unique contribution. Reuse Document Profile fields from progressive reading.

## 2. Individual Understanding
Understand each source sufficiently to preserve its actual claims and evidence boundaries. Use a compact version of Progressive Reading unless a source deserves full Deep treatment.

## 3. Cross-source Map
Map:
- overlap
- unique contributions
- dependencies
- incompatible assumptions
- different definitions or evaluation conditions

## 4. Core Mental Models
Extract 3–5 thinking tools only when supported. A mental model should help interpret new information; it is not a feature list or recap.

For each:
- What it is
- How it changes reasoning
- Supporting sources
- Applicability boundary

## 5. Agreements and Expert Disagreements
Separate:
- genuine agreement
- apparent agreement using different definitions
- genuine disagreement
- different answers to different questions

For each genuine disagreement:
- Position A + strongest evidence/source
- Position B + strongest evidence/source
- Why the disagreement matters
- What evidence could resolve it
- Current state: settled / active debate / emerging / insufficient evidence

Never invent a second side merely to make a debate symmetrical.

## 6. Collective Knowledge Gaps
Ask what a reader still needs to know that the source set does not adequately cover:
- assumed prerequisites
- collective blind spots
- missing populations/tasks/environments
- temporal gaps
- missing negative evidence
- missing operational or cost dimensions

## 7. Knowledge Stress Test
Generate 5–8 questions only when learning depth matters. Questions should require transfer, boundary reasoning, assumption testing, or application—not sentence copying.

Each question states what understanding it tests.

## 8. Teachable Framework
Create only when the evidence naturally supports a reusable structure.

Include:
- framework name (only if natural)
- dimensions/steps/decision criteria
- when to apply
- how to apply
- limitations
- which sources support each important element

Do not force acronyms or pretend an inferred framework is source-authored.

## 9. Optional Learning Path / Audience Adaptation
Run only when explicitly useful for learning, teaching, presentation, or decision preparation. These are capabilities, not mandatory sections.
