# 跨平台 plugin 安裝包與使用場景 — 設計

- 日期：2026-11-09
- 分支：`feat/cross-platform-plugin-installer`
- 查核基準：`fe55c04bf9202fe82f1a68b7f5985305c82249f0`
- 狀態：設計與計畫已核准，離線候選版已實作；原生驗收與完整安裝能力仍有缺口，見 [驗證紀錄](../../validation/plugin-installer/README.md)。

## 目標與交付

提供一份可發給同事的壓縮安裝包，內含 Windows、macOS、Linux 各自的啟動入口。讓同事選擇 Claude Code、Codex 或兩者，了解各 plugin 提供的 skills 與限制，確認後安裝。英文 `README.md` 與繁中 `README.zh.md` 同步補上單包及多包搭配的使用場景。

安裝包包含啟動程式、共用 Python 主程式與套件資料清單；plugins 由原生 CLI 從指定 marketplace 下載，因此需要連網。這次交付是安裝器與說明，不包含修改所有 plugins 以支援原生 Windows。

## 已確認的決定

| 項目 | 行為 |
| --- | --- |
| Claude Code／Codex | 只偵測與提供缺少時的安裝指引，不代裝主程式或處理帳號登入 |
| 安裝對象 | 同事選擇一個或兩個已安裝的 CLI；不可選未安裝者 |
| 本 repo 的套件 | 預設全選適用套件，確認前可取消；列出用途、skills、必要工具與限制 |
| Claude Code 額外選項 | 提供 `handoff-mod` 與 `attention-mod`；不把它們列成 Codex 可用套件 |
| Superpowers | 獨立列為「強烈建議安裝」，說明用途與未安裝的影響；預設不勾選 |
| 第三方工具 | 只使用電腦現有且受安裝器支援的套件管理工具；列出計畫並取得同意後代裝 |
| 缺少套件管理工具 | 提供指引，不再代裝 Homebrew、WinGet 等管理工具 |
| 已安裝 plugins | 預設保留；更新必須另行勾選並確認 |
| 首次日誌設定 | 提供可略過的引導，解釋活動與筆記資料夾用途，預覽後才寫入 |
| 個人設定 | 保留既有設定；錯誤設定回報，不以預設值覆蓋 |
| 部分失敗 | 繼續處理其他獨立項目，列出失敗與略過原因；不自動重試或移除已裝好的工具 |
| Python 例外 | Python 是共用主程式的必要條件；無法補齊時停在引導，不進入完整安裝流程 |
| 權限與信任 | 依宿主原有流程確認；不自動授權 hooks，不繞過公司政策 |
| 變更授權 | 文件審閱、實作計畫、commit 與實際對外安裝測試分開處理 |

「適用」指 CLI 的安裝選項，不代表所有 skills 的功能已在該作業系統驗收。Windows 的已知限制與未驗證項目在選單及結果中都須可見。

## 架構與安裝計畫

### 平台啟動檔

Windows 使用 PowerShell，macOS／Linux 使用 shell。啟動檔只負責最低限度的環境檢查、Python 補裝引導與啟動主程式，不另寫完整 plugin 安裝規則。

先確認至少有一個目標 CLI 可用，再處理 Python，避免沒有安裝對象時仍要求補裝工具。Python 缺少時只呼叫現有管理工具，先顯示來源、動作與權限要求；拒絕或失敗即提供指引。探測 Python 不得觸發 Store 別名或安裝管理程式自行下載 runtime；Windows 的實際探測與重啟後辨識方式須先用隔離環境驗證。

### 共用 Python 主程式

只使用標準函式庫，負責環境盤點、選單、產生計畫、預覽、確認、安裝執行、設定引導及結果報告。平台命令與兩個 CLI 的差異由各自的執行介面處理。

每個項目以「CLI＋plugin＋來源」識別，記錄目前狀態、預定動作、預期版本、依賴、確認範圍及執行結果。例如 Claude Code 已裝某包而 Codex 未裝，預設前者保留、後者安裝，不合併成單一狀態。

預覽與執行使用同一份安裝計畫。執行端不能自行追加未預覽的安裝、更新或設定寫入。若環境或來源變化使計畫失效，暫停受影響項目；產生新預覽並重新確認後才可繼續。

### 套件資料清單

從 `plugin-packages.json`、兩個 CLI 實際生成的 manifests／skills，以及 Claude marketplace 定義產生資料；七包、兩個 Claude 額外 plugins 與 Superpowers 的來源分類須分開。不得只把來源層的 skills 聯集當成兩個 CLI 都具有的入口。

`requirements.commands` 作為已宣告依賴，還要核對選定功能實際使用的腳本；欄位空白不等於不需要工具。Superpowers 的來源、identity、版本與適用入口單獨核對，不因快取目錄存在或名稱相同就認定已安裝、相容。

安裝包附帶資料有來源版本以供追查。安裝時還要比對當次 marketplace 清單；內容不符時不能繼續把舊說明當成將安裝的內容。

## 同事的操作流程

| 步驟 | 畫面與行為 |
| --- | --- |
| 1．檢查環境 | 顯示兩個 CLI 狀態；需要時先提供主程式指引，或詢問補裝 Python |
| 2．選擇安裝對象 | 可選 Claude Code、Codex 或兩者；未安裝者標示原因且不可選 |
| 3．確認來源並選套件 | 需要新增或刷新 marketplace 時先獨立預覽確認，再取得當次清單；套件預設全選，已裝者保留，更新另選 |
| 4．檢視安裝計畫 | 顯示新增、更新、保留、略過、缺少工具與下載來源；可返回修改或取消 |
| 5．確認並安裝 | 執行已同意項目，遇到失敗記錄原因；其他獨立項目可繼續 |
| 6．設定與結果 | 提供可略過的日誌設定；另行預覽確認寫入，最後列出結果與後續動作 |

文字選單以編號或等效的明確選擇操作，不要求同事自行組合安裝命令。程式輸出與程式碼註解依 repo 慣例使用英文；README 同時提供英文與繁中說明。

Superpowers 選項必須顯著標示強烈建議，具體說明實作計畫、測試驅動開發等相關流程；不選擇時保留其他套件的獨立用途，不把整體安裝判成失敗。

## 來源、版本與外部動作

只操作列入計畫的 marketplace 與 plugins。已有同名 marketplace 時先核對來源；來源衝突就暫停受影響項目，不直接替換。已停用、由專案或組織管理的項目不能因使用者層級的安裝而被默默改動；無法辨識時標示待確認。

新增或刷新 marketplace 本身可能連網與修改宿主資料，因此在完整套件安裝之前要先單獨顯示、取得確認。讀取本機狀態與連網刷新不能混報成全程唯讀。

套件預覽顯示來源與預期版本，執行前後再核對；來源改變或無法確認裝入內容時標為待確認，暫停同來源受影響項目，不報驗證成功。兩個 CLI 的版本固定能力仍須實測，不承諾已具備相同的精確鎖版能力，也不以事後版本核對宣稱消除了安裝中的來源變動。

代裝依賴只處理選定功能需要且缺少的工具。預覽要說明所需權限與管理工具會帶入的依賴；無法可靠列出的影響要明說，不能宣稱只寫入一個程式。通過管理工具的安裝命令不等於通過 plugin 功能驗證，完成後需重新檢查命令是否確實可用。

安裝器不主動重跑失敗的外部動作；同事主動重跑時重新盤點並確認新的計畫。維護者執行實際下載或安裝測試前，另提具體隔離範圍；已執行過的對外操作若要重跑，依專案規則重新取得批准。

## 設定與使用者資料

首次日誌引導解釋活動紀錄與筆記資料夾用途，讓同事選擇位置。預覽包含設定檔與可能建立的資料夾；確認後才寫入。保留有效的既有設定；既有內容無效則回報，不將其視為不存在。略過設定時顯示「已安裝、待設定」。

沿用 runtime 的外部共用設定根目錄解析，不把個人資料或安裝狀態寫進 plugin 快取。設定引導不讀取筆記內文，不搬移或刪除既有活動與筆記。重新檢查與寫入之間若有其他程序修改設定，須保留該變更並回報衝突。

安裝器不修改同事的 `CLAUDE.md`／`AGENTS.md`，不自動遷移 standalone skills，也不寫入個人語氣覆寫或 hook 信任。原生 Windows 已知不支援的偏好寫入與遷移，繼續列為功能限制；本次不修補其 POSIX 檔案鎖實作。

## 失敗、取消與結果

安裝結果、設定完成度與待授權事項分開記錄，避免用「待設定」蓋掉已完成的安裝，或用安裝成功掩蓋尚未授權。

| 結果 | 判定 |
| --- | --- |
| 已安裝或已更新 | 原生命令結果及事後 inventory 符合計畫中的來源、版本與狀態 |
| 已保留 | 偵測到原有項目，未選更新，未對該項執行變更 |
| 已略過 | 同事未選、缺依賴、前置項失敗或來源衝突，且未執行安裝 |
| 失敗 | 有明確失敗證據，保留原因與下一步 |
| 待確認 | 命令中斷、逾時或回傳格式不符，無法確認是否已有寫入；不可當成完全未變更 |

另列待設定、待重啟、待 hook 信任與未驗證功能。成功、失敗與略過可同時存在，不能只回報一個「全部成功」。

執行前取消，不執行尚未同意的安裝、更新或設定寫入；先前已單獨確認的 Python 補裝或 marketplace 刷新仍可能已完成，結果須保留。執行中取消則停止後續動作，核對當前項目並報告實際進度，不自動回復或移除成功項目。

一包失敗只阻擋依賴它或共用失效來源的項目；其他獨立項目繼續。權限遭拒、下載失敗、無可用工具或不支援的 CLI 能力，要提供可理解的原因與補救指引。

## README 的使用場景

英文 `README.md` 與繁中 `README.zh.md` 以工作情境組織，正文提供範例，不只列出套件名稱或觸發詞。每個場景說明使用時機、需要的套件、如何開始及預期產出；對照表讓讀者從任一套件反查場景。

| 場景範圍 | 覆蓋套件 |
| --- | --- |
| 接到模糊需求，形成設計、計畫，再審查與驗證修改 | `technical-decisions`、Superpowers、`quality-gates` |
| 理解既有程式、開新任務、留交接並在下次接手 | `repo-workflow` |
| Claude Code 長任務中查看目前注意事項與整理交接 | `attention-mod`、`handoff-mod`；能力與入口依實際內容核對 |
| 記錄工作，回顧紀錄並整理報告 | `work-journal` |
| 將素材整理成簡報、翻譯或對外文字 | `content-tools`；需要時搭配日誌資料或技術分析 |
| 調整回應語氣、說明深度與歸還控制權規則 | `session-preferences` |
| 找適合的 skill，或檢查自己的 skill 品質 | `skill-toolbox` |

範例使用各 CLI 真正具有的入口，區分自然語言觸發、必須手動呼叫與需額外安裝的步驟。必要設定、平台限制及外部服務需求隨範例說明；不宣稱安裝等於授權、所有 skills 全平台通過，或全部工作都不需額外工具。

## 驗收與完成標準

### 離線與模擬 CLI

先用暫存設定與模擬 CLI 驗證行為，不下載工具、不修改維護者的實際安裝環境。測試要檢查實際命令、檔案與結果，而非只斷言模擬物件回傳成功。

| 驗收項目 | 必須包含的情況 |
| --- | --- |
| 啟動 | 主程式未安裝、Python 缺少／拒絕／補裝失敗、管理工具不存在、探測不觸發下載 |
| 選擇與預覽 | 單 CLI／雙 CLI、七包與 Claude 額外選項、Superpowers 強烈推薦但未預選、返回與取消 |
| 計畫一致性 | 預覽與執行逐項一致，依賴安裝後重驗；來源或本機狀態變更不得沿用失效確認 |
| 重跑 | 原有套件保留、明確更新、已停用或其他層級管理項目、部分完成後補裝 |
| 錯誤與取消 | 權限拒絕、下載失敗、逾時、無效 JSON、來源衝突、執行中取消、獨立項目繼續 |
| 設定 | 首次建立、既有有效／無效設定、同時修改、略過、空白與中文路徑、資料不搬移 |
| 安裝包與文件 | 解壓後入口、可搬移路徑、資料清單與產物一致、README 套件與場景對照完整 |

### 原生驗收

原生驗收對象為 macOS、原生 Windows、Ubuntu／Debian。記錄每次的作業系統、架構、CLI 版本、套件來源／版本與實際結果；測過其中一種 Linux 或架構不代表其餘組合通過。其他 Linux 發行版先標為未驗證，無受支援的代裝方式時提供指引。

實際下載與安裝使用另外批准的隔離環境與具體命令範圍，不複製維護者的私人認證。安裝器預設不啟動模型 session 或送出真實工作資料；若功能驗收需要額外登入、外部呼叫或費用，必須另列範圍取得批准。

hook 信任維持人工流程。CLI 清單與設定核對只能證明安裝層，不代替 hooks、MCP 與所有 skills 的執行驗收。沒有取得原生證據的組合列為未驗證，不對外宣稱已支援驗收完成。

交付檢查包含可重現產生的壓縮包、對應來源版本、驗收紀錄，以及兩份 README 的場景與平台限制。若實作修改到 plugin payload，另外遵守既有升版、產物重建與發布門檻；安裝包完成不代表已發布 plugins。

## 方案比較與證據

| 方案 | 取捨與最可能失敗原因 | 決定 |
| --- | --- | --- |
| 平台啟動檔＋Python 標準函式庫主程式 | 集中維護規則；Python 無法補齊就無法進入完整流程 | 採用，使用者已接受 Python 例外 |
| 各平台各寫完整腳本 | 無共同 Python 主程式前提；需維護兩份規則與狀態解析，容易行為不一致 | 不採用 |
| 各平台打包執行檔 | 安裝器不依賴外部 Python；增加各平台建置、架構與發布驗收，內附 Python 不等於滿足 plugin runtime | 第一版不採用 |

`tech-feasibility` 的條件式可行結論與 `critical-research` 的反證一起決定取捨：現有管理工具可提供依賴安裝，但不能保證每台電腦都能補齊 Python，因此明列啟動例外，而非宣稱零前置條件。`research-synthesis` 將此取捨納入同一份設計，未另行批准 commit。

本次已查核：本機 CLI 的 help 列出 JSON plugin 清單；Claude 與 Codex 的安裝、更新及 marketplace 介面不完全相同。這只證明命令入口存在，尚未驗證 inventory 欄位與遠端安裝結果。

來源程式也確認 `save_module_override` 與部分遷移使用 POSIX 檔案鎖。日誌首次設定是另一條程式路徑，不得因偏好寫入的限制就推論所有 Windows 設定都失效，也不能未經原生測試就宣稱日誌設定已支援。

### 待驗證事項及影響

| 待驗證事項 | 驗證前的處理 |
| --- | --- |
| CLI inventory 欄位、啟用狀態、管理層級與實際版本 | 不以快取目錄或 help 取代實際安裝證據；無法辨識則待確認 |
| 遠端來源固定、刷新與更新行為 | 未確定的路徑不能報版本驗證成功 |
| 各平台 Python 探測、可用命令名稱與安裝後 PATH | 隔離驗證，避免探測觸發安裝或安裝後仍不能被 plugins 呼叫 |
| 各管理工具的套件 ID、版本需求與額外依賴 | 核對後才納入代裝清單，不根據名稱猜測或代裝管理工具 |
| Superpowers 來源、宿主註冊與相容性 | 從原生 manifest／實際暴露入口確認；未測版本不宣稱相容 |
| 原生 Windows 日誌設定、shell 功能及啟動政策 | 保留明確限制與待設定／未驗證狀態，不繞過政策 |
| 原生平台與 CPU 架構矩陣 | 只對取得證據的組合宣稱驗收通過 |

## Superpowers 來源決議補充（2026-11-10）

使用者已確認：「優先使用各 CLI 官方目錄提供的版本，再分別驗收需要的功能。」

Claude Code 與 Codex 可以採用不同版本；不把先前觀察到的 `7.0.2` 當作兩邊統一版本或最低版本要求。「官方目錄收錄」與「coding agent 主動推薦安裝」分開描述，不宣稱後者已獲證實。

延用既有規則：Superpowers 強烈建議但預設不勾選；保留已安裝套件與個人設定；來源、版本、實際入口及流程相容性分開驗收。這項來源決議不授權降版、替換既有 provider、直接寫入宿主的受管理目錄，或執行新的對外安裝／模型測試。

來源快照、Codex 官方目錄的特殊限制與後續設計候選，見 [官方來源策略查核](../../validation/plugin-installer/superpowers-official-source-strategy.md)。本節記錄已核准的來源原則；報告中的實作候選仍待設計審閱。
